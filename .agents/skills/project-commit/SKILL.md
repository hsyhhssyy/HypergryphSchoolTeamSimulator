# 项目提交

提交前读取 [提交流程](references/workflow.md)，审计整个工作区，并使用仓库根目录的 `commit-all.sh` 将全部改动作为一个整体提交。

## 权限边界

- 用户要求修改、修复、测试或检查代码，不等于授权提交。
- 提交授权不等于授权推送、建分支、创建 PR、发布或重写历史。
- 不得为得到整洁提交而删除、还原、覆盖或隐藏用户已有改动。
- 不得使用 `--no-verify` 绕过 hooks，也不得在未经明确要求时使用 `--amend`。
- 不区分 AI、本次任务、用户或其他协作者产生的改动；用户要求提交时，默认提交当前工作区的全部 tracked、untracked 和已暂存改动。
- 不得以“只提交我的改动”为由选择性暂存、拆分提交，或要求用户先处理其他改动。
- 审计改动只用于发现不可提交状态、生成覆盖全部改动的提交信息和准确汇报，不用于筛选改动归属。

## 结果要求

提交成功后报告 commit hash、提交标题、包含的改动范围和提交前已知的验证结果；若未执行测试，应明确说明。
